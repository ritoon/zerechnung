# Écarts connus et justifiés entre ZeRechnung et les validateurs de référence.
#
# Une ligne par écart : référence, facture, écart, raison.
#   référence : kosit, mustang, npa (XSLT de la NPa), fnfe (XSLT
#               EXTENDED-CTC-FR de la FNFE-MPE), pt (schematron CIUS-PT
#               d'eSPap) ou * (toutes)
#   facture   : origine de la facture (corpus/…, kosit/…, variants/…, nl/…,
#               fr/… ou pt/…) ; * vaut pour n'importe quelle suite de
#               caractères, / compris
#   écart     : +RÈGLE en erreur chez ZeRechnung seul, -RÈGLE en erreur chez la
#               référence seule (avec les variants, npa, fnfe et pt, à tout
#               niveau : + ou - pour le côté qui la lève au niveau le plus
#               élevé) ; ?RÈGLE attendue par le test de mutation d'un variant
#               et que la référence ne lève pas ; une * finale vaut pour toutes
#               les règles de ce préfixe ; SCHEMA désigne les erreurs de schéma
#               XSD. Avec pt, la règle est suivie de l'élément où elle est
#               levée, +RÈGLE@/Invoice[1]/InvoiceLine[2], sauf pour
#               l'assertion d'un arrêt de Saxon (-RÈGLE)
#   raison    : le reste de la ligne, obligatoire
#
# Un écart absent de ce fichier fait échouer le job de parité ; une ligne qui
# ne correspond plus à aucun écart est signalée dans le rapport.
#
# Schematron CIUS-PT : aucun écart connu. Un arrêt de Saxon sur une erreur de
# type XPath dans le test d'une assertion n'est pas un écart quand ZeRechnung
# lève cette assertion, qu'il tient pour échouée (voir le README).

#
# Sur un élément répété là où le schéma n'en admet qu'un, le test d'une règle
# CEN reçoit deux valeurs (normalize-space, substring-after, cast) et Saxon
# arrête la transformation (XPTY0004). ZeRechnung lit la première valeur, et
# signale la répétition par sa règle de syntaxe ou par le schéma XSD : même
# verdict.

# XSLT de la NPa : assertions NLCIUS qu'aucune facture ne fait échouer
#
# Dans un motif schematron, un élément n'est vérifié que par la première règle
# dont il vérifie le contexte : ces assertions ne s'appliquent jamais, et
# ZeRechnung ne les implémente pas (voir la documentation de internal/rules/nl).

npa cii/nlcius ~BR-NL-9 Même contexte que BR-NL-7 (/*/rsm:ExchangedDocument/ram:TypeCode[$si]), qui le précède dans le motif.

npa ubl/nlcius ~BR-NL-32-1 Assertion au message de BR-NL-34 : sa règle répète le contexte de BR-NL-32-1 (cac:AllowanceCharge/cbc:AllowanceChargeReasonCode), qui la précède dans le motif.
npa ubl/nlcius ~BR-NL-32-2 Les deux assertions BR-NL-32-2, aux messages de BR-NL-32 et de BR-NL-34 : le contexte de BR-NL-32-1, cac:AllowanceCharge/cbc:AllowanceChargeReasonCode, couvre déjà les codes motifs des remises et charges des lignes de facture.
npa ubl/nlcius ~BR-NL-32-3 Les deux assertions BR-NL-32-3, aux messages de BR-NL-32 et de BR-NL-34 : le contexte de BR-NL-32-1 couvre déjà les codes motifs des remises et charges des lignes d'avoir.
